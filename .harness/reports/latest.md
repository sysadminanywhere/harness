# Автоматическое обновление процессов

## Уточнено правило для исполнителей

В `AGENTS.md` добавлено требование периодически обновлять промежуточный прогресс в `.harness/reports/latest.md` во время длительной работы. Финальный отчёт после завершения сохраняется отдельным обязательным шагом.

## Отчёт исполнителя обновляется по мере работы

Codex-мост теперь записывает промежуточный прогресс в отчёт конкретного запуска и в `.harness/reports/latest.md` после каждого значимого события. Одновременно обновляются `status.json` (`progressEvent`, `progressMessage`, `progressAt`), поэтому блок «Исполнитель» показывает свежий текст во время работы, а не только после завершения.

## Изменённые файлы

- `codex-bridge.js`
- `server.js`

Доска получает свежий план, очередь, статусы, запуски и события каждые 2 секунды. Открытый отчёт обновляется вместе с журналом, сохраняя фильтры и выбранный запуск. Добавлены индикатор последнего обновления, сообщение об ошибке связи и автоматические повторные попытки. При возвращении на вкладку, фокусе окна и восстановлении сети выполняется обновление.

Защита: нет параллельных циклов синхронизации; запрос ограничен 10 секундами; запоздавшие ответы другого проекта или до сохранения отбрасываются; синхронизация откладывается во время ввода в диалогах, сохранения и перетаскивания.

- Добавлена нормализация `idea → inbox` и `completed → done` при чтении и сохранении планов.
- Добавлена регрессионная проверка совместимых статусов в smoke-тест.
- Проверки: `npm test`, `git diff --check`, реальный HCM API: 19 карточек, 7 идей видны в `inbox`, 0 карточек осталось со статусом `idea`.

## Работа Harness в открытом Codex проекте

- Добавлен локальный мост `codex-bridge.js` через `codex exec --json`.
- При запуске карточки Codex получает корень подключённого проекта через `--cd`, создаёт сохраняемый Codex-сеанс и публикует JSONL-события прогресса в `.harness/events.jsonl`.
- `threadId`, путь проекта, ссылка `codex://threads/...`, статус и код завершения сохраняются в `.harness/status.json` и запуске.
- На панели исполнителя появляется ссылка «Открыть в Codex» после получения идентификатора треда.
- При недоступном Codex процесс не ломает обычный Harness: ошибка сохраняется в статусе и журнале.
- Проверки: `npm test` с отключённым bridge для детерминированной регрессии, проверка CLI `codex exec --help`, `git diff --cached --check`.
- Изменены файлы: `codex-bridge.js`, `server.js`, `board.js`, `package.json`.
