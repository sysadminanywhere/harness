# Аудит реализации Harness — 2026-10-25

Проверены сервер/API, очередь и исполнители, восстановление, файловое состояние, формы и синхронизация доски, модели, импорт, onboarding, PWA и Windows desktop runtime. Проверки выполнялись в изолированных проектах; задачи реализации HCM не запускались. Предыдущие пользовательские изменения сохранены.

## Найденные и исправленные дефекты

| Область | Дефект и исправление |
| --- | --- |
| Подключение проекта | Повторное подключение заменяло существующий план шаблоном. Существующий plan.json сохраняется; пустой путь отклоняется. |
| Очередь | Невыполнимая первая задача останавливала остальные. Worker проверяет все заявки, запускает доступную, сохраняет blockedReason для остальных. |
| Локальные команды | Фоновая команда при занятом исполнителе возвращала ошибку. Теперь ставится в очередь и сохраняет параметры команды. Синхронный command API по-прежнему возвращает busy. |
| Допуск к запуску | Command API обходил зависимости и approval карточки. Все пути запуска проверяют их и политику проекта. Задача CLI/PowerShell без команды больше не имитирует работающего исполнителя. |
| Retry команды | У ad-hoc команды не сохранялись параметры для Retry. Они включены в run.input; проверен повтор без карточки. |
| Автономность | «ИИ берёт сам» работало только при открытой вкладке. Серверный worker подбирает ready/auto задачи и разрешённые адаптеры; manual policy и зависимости соблюдаются. |
| Архивирование | Retention мог убирать активные, queued и привязанные к карточкам запуски. Эти записи теперь исключены из архивации. |
| Откат плана | Rollback обходил защиту работающих карточек. Применяется та же защита, что при сохранении плана. |
| Перезапуск | Потерянная CLI/PowerShell-команда оставалась working. При восстановлении она становится failed/blocked. |
| Закрытие desktop | Завершение сервера оставляло дочерние процессы. Electron передаёт IPC shutdown; сервер останавливает дерево исполнителя и сохраняет отмену. Проверено на настоящем процессе Node. |
| Windows упаковка | npm запускался через Electron без ELECTRON_RUN_AS_NODE и зависал. Режим Node сохраняется в окружении команд. Старый пакет воспроизвёл timeout; новый выполнил npm test. |
| Входные данные | null-карточка и неправильные типы списков могли уронить сервер. Добавлена проверка формата, дубликатов и циклов родителей; старые статусы и карточки без title совместимы. |
| Недоступные файлы | Ошибка файлов одного проекта могла оборвать HTTP-сервер. Возвращается ошибка хранения, остальные проекты продолжают работать; ошибки callback записи также обработаны. |
| Сохранения UI | Два быстрых сохранения конфликтовали друг с другом. Локальные сохранения используют подтверждённую ревизию; внешний конфликт остаётся защищённым. |
| Конфликт формы | Ошибка сохранения не обрабатывалась; повторная отправка опережала обновление плана. Форма сохраняет черновик и ждёт загрузки актуального состояния. |
| Смена проекта | Старый редактор и запоздалый load могли затронуть новый проект. Редактор закрывается, ответы проверяют проект, последовательность и поколение изменений. |
| Импорт | Замена ID теряла parentId/dependencies. Связи переназначаются через таблицу ID. Ключи Markdown-плана стабильны; изменение текста учитывается в hash. |
| Предпросмотр | Escape оставлял незавершённый Promise импорта. Закрытие разрешает его как отказ от применения. |
| Имена проектов | Имена вставлялись через innerHTML. Используется текст DOM option; проверено имя с угловыми скобками и &. |
| Контекст Codex | Constraints отсутствовали в prompt. Передаются ограничения и инструкция сохранить идентификаторы активного запуска. |
| Файловый мост и ручной результат | Внешний completed не попадал в run/report, поэтому результат нельзя было принять. Актуальный отчёт IDE/человека синхронизируется с запуском. Для ручных задач добавлена отправка описания результата на проверку, затем обычное принятие. |
| Восстановление старых ошибок | Цитата ошибки в пользовательском контексте ошибочно считалась сбоем запуска. Историческая коррекция теперь требует диагностического события или результата инструмента. Добавлена регрессия на цитату; ошибочно изменённая запись собственного предыдущего отчёта восстановлена. |

## Подтверждённые проверки

- `npm test`: PASS — синтаксис, 22 unit/model/bridge tests, smoke, runtime, controls/model integration и 12 сценариев `audit-test.mjs`.
- `HARNESS_BROWSER_MODELS_OK`: настройки проекта, наследование группы, override задачи, reload, модель активной попытки, Retry.
- `HARNESS_BROWSER_AUDIT_OK`: десять сценариев — быстрые сохранения, внешний конфликт с сохранением черновика, Escape, стабильные ключи, импорт связей, reload, имена проектов, смена проекта, ручной результат с принятием, onboarding и подключение через форму. Ошибок JavaScript в этом probe нет; HTTP 409 специально воспроизводится для проверки конфликта.
- Browser controls: отмена активной/queued задачи, pause/resume, Retry с новым runId, принятие/возврат исторического результата, отмена реальной команды и сохранение после reload. API controls дополнительно проверены автоматическим набором.
- `HARNESS_REAL_CONTROLS_OK`: настоящий Codex paused/resumed с сохранением thread.
- `HARNESS_REAL_TOOLS_OK`: настоящий Codex успешно выполнил PowerShell-команду в отдельном временном Git-проекте.
- `electron-builder --win --dir`: собрана Windows x64 unpacked-версия. `HARNESS_PACKAGED_RUNTIME_OK`: сервер запущен через собранный Harness Lab.exe, статические файлы читаются из asar, каталог моделей доступен, npm adapter действительно выполнен, IPC shutdown отработал.
- PWA zip собран с актуальными серверными модулями. Проверена граница staging-каталога перед очисткой.
- `git diff --check` и `git diff --cached --check` выполняются при завершении.

## Границы проверки

NSIS/portable installers, установка на чистую машину, Linux/macOS и полная UI-локализация не проверялись в этом аудите. Windows desktop проверен как unpacked-сборка и её реальный серверный runtime; отдельный ручной проход по native menu не выполнялся. Большинство lifecycle API-сценариев используют отключённый Codex bridge, а реальные Codex start/tool/pause/resume подтверждены отдельными probes. Это локальная техническая проверка Harness, а не приёмка реализации HCM.
