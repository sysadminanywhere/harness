# Работа по целевому сценарию — 2026-10-25

Продолжение [аудита реализации](IMPLEMENTATION_AUDIT.md). Здесь перечислены дополнительные исправления, проверенные после просьбы довести поведение до задуманного сценария.

## Основной интерфейс

- Раздел «Исполнение» заменён: он показывает реальные runId, исполнителя, модель, события и отчёт выбранного запуска. Действия используют тот же API, что карточки: отмена, пауза/продолжение, Retry, ручной результат и принятие.
- Старая демонстрация с вымышленными инструментами, diff и проверками удалена из рабочего интерфейса. Боковая история открывает настоящие отчёты проекта; «Новый план» открывает локальный планировщик и создаёт реальные карточки без имитации исполнения.
- Цель и ограничения планировщика сохраняются в каждом шаге и передаются исполнителю.
- Исторический запуск не получает отчёт другой попытки и не управляет новым запуском той же карточки.

## Очередь и автономность

- Авторун выполняет серверный worker; дублирующий браузерный планировщик удалён.
- Заблокированная очередь не мешает запустить автоматическую предпосылку. После её выполнения результат остаётся на проверке; принятие открывает зависимую заявку.
- Автономные задачи выбираются по приоритету и дедлайну, а не расположению карточек.
- Dry-run не запускается автоматически и не превращается в реальное исполнение при Retry. Новый run при просмотре не создаётся.
- Неподдерживаемая команда проверяется до попадания в очередь. PowerShell через CLI сохраняет переданные пользователем аргументы.
- Фоновый обход больше не читает полные отчёты и не запускает Git для каждого простаивающего проекта.

## Сохранность состояния

- Сохранения сериализуются отдельно для каждого проекта. Задержанный запрос A не блокирует B и не подменяет его доску поздним ответом.
- При переключении действия и сохранение недоступны до загрузки выбранного проекта. Асинхронные ответы импорта, планировщика, истории и отката остаются в своём контексте.
- Reconnect сохраняет модель, policy и allowedAdapters. Windows-регистр пути и алиасы не создают повторную регистрацию одной папки.
- Импорт создаёт новые задачи без чужих runId, разрешений запуска и автоматического исполнения. Связи parentId/dependencies переназначаются. CSV поддерживает запятые, escaped quotes, переносы строк и BOM.
- Нельзя создать карточку «В работе» без запуска либо привязать чужой/несуществующий run.
- Потерянная папка не пересоздаётся как пустой проект. Недоступный проект можно отключить от реестра; его файлы не удаляются. Повреждённый projects.json возвращает ошибку и сохраняет исходные байты.
- Запросы изменения состояния с чужим Origin и нелокальным Host отклоняются.

## Файловый мост

Завершение, ошибка и отмена IDE/ручного исполнителя синхронизируются с run.json, отчётом и карточкой. При старте сохраняется `.harness/active-run.json`; постановка другой задачи в очередь его не заменяет. Если старый исполнитель сохраняет taskId, но пропускает runId, Harness восстанавливает идентификатор текущего незавершённого запуска из этой записи или карточки. Для принятия успеха нужен изменившийся после старта latest.md либо отчёт внутри каталога конкретного runId. Старый отчёт не объявляется новым результатом. Пауза и отмена без активной попытки не создают фиктивный запуск.
