# Сквозная приёмка Harness Lab

Дата последней проверки: 2026-10-25

Актуальные результаты полного технического аудита, исправления и границы проверки: [IMPLEMENTATION_AUDIT.md](IMPLEMENTATION_AUDIT.md). В ходе аудита подтверждены браузерные сценарии, реальные Codex tool/pause/resume и Windows packaged runtime. Описанные ниже ограничения старой приёмки относятся к её первоначальному запуску.

## Подтверждено локально

- `npm test` — syntax-check и API smoke проходят.
- Smoke проверяет проекты, план, очередь, приоритет/дедлайн, duplicate queue protection, `runId`, сохранение `run.json`/`report.md`, адресное управление и принятие завершённого запуска.
- `npm run package:pwa` — успешно создаёт `release/harness-lab-pwa-v0.1.0.zip`.
- `git diff --cached --check` — проходит.
- Встроенный browser runner: созданы Acceptance A/B, A запущена, следующая задача поставлена при активном исполнителе, выполнено переключение A ↔ B.
- После остановки и повторного запуска сервера UI восстановил выбранный проект, активный исполнитель и queued-карточку.

## Не подтверждено

- Переход A в `review` требует внешнего завершения Codex-исполнителя; локальный UI-сценарий подтверждает только активное состояние и очередь.
- Визуальное отображение истории `runId` отдельным экраном ещё требует отдельной UX-задачи.

## Причина

CLI `npx --yes --package @playwright/cli playwright-cli` зависает без вывода, поэтому сценарий выполнен через встроенный browser runner. Это не заменяет внешний Codex-исполнитель, которого в локальном acceptance-сценарии нет.

## Следующий запуск при доступном браузерном CLI

1. Запустить сервер с отдельным временным workspace и включённым worker.
2. Создать два проекта и задачи A/B через UI.
3. Запустить A, поставить B в очередь, проверить `runId`, queued и переход A в review.
4. Перезапустить сервер и убедиться, что история запусков и план сохранены.
5. Повторить с двумя вкладками для проверки revision-конфликта.
